# Финальная ревизия Death Strike и Identify Monster

Статус: **Research / Proposed**, 2026-10-15. Исходный код: `142a54e01da50d9faf258e38919e88dba9e8de29`.
Новые механики не реализованы; игровой код, баланс, ресурсы и CI не изменены; сборка не запускалась.
Эта ревизия уточняет прежние исследования, а не отменяет сохранённые результаты Windows build #3.

## 1. Доступность навыка и расхождение Windows build #3

Фактически запрашиваемый путь — `engine/data_tables/class_skills.txt`, а не legacy-таблицы
MM8/MMerge. [GameDataLoader::loadClassSkillTable](../../game/data/GameDataLoader.cpp:3157)
передаёт строки в [ClassSkillTable::loadCapsFromRows](../../game/tables/ClassSkillTable.cpp:110).
[TextTable](../../engine/TextTable.cpp:34) сохраняет пустую первую ячейку заголовка: смещения
колонок здесь нет. `class_extra.txt` задаёт соответствие ID/имени/ветви продвижения,
`class_starting_skills.txt` — стартовый выбор, а `class_multipliers.txt` — ресурсы, не caps.

После загрузки [applyMergedRuntimeTables](../../game/data/GameDataLoader.cpp:3753) применяет
`race_skills.yml`; [getEffectiveCap](../../game/tables/ClassSkillTable.cpp:380) вычисляет
`clamp(max(baseCap,raceMin)+raceAdd)` с add только при baseCap != None.
Правила фильтруются по race ID, class kind и exception. У race3 нет IdentifyMonster override;
у race5 есть add1; у Human/race0 и Undead/race6 такого правила нет.
Все вызовы loadCapsFromRows/applyRaceSkillOverrides в game проверены: отдельной
Minotaur-поправки IdentifyMonster и второго слоя class-cap overlays не найдено.

Пути возможного расхождения разделены:

| Слой | Что может изменить | Результат проверки |
| --- | --- | --- |
| VFS | Другой файл под тем же virtual path | [AssetFileSystem](../../engine/AssetFileSystem.cpp:720): development mounts; packaged `engine.zip` монтируется в `/engine`; порядок PhysicsFS определяет найденный файл. Нельзя считать файл из checkout доказательством содержимого установленного ZIP |
| Class/race tables | Возможность обучения | Minotaur/Lord None; Necromancer/Lich Master; расовое исключение Minotaur не даёт IdentifyMonster |
| Реальный className/raceId | Какие правила применяются | Раса Minotaur сама по себе не означает класс Minotaur; другой класс может иметь Expert или выше |
| Стартовый выбор | Начальные навыки | Для Minotaur IdentifyMonster `-`; не объясняет Expert |
| Save/roster/events | Уже выданный навык | [EventRuntime](../../game/events/EventRuntime.cpp:3218) непосредственно записывает level/mastery без cap; загрузка/готовый персонаж не доказывают обучение у учителя |
| Предметы | Эффективное число навыка | [ItemEnchantRuntime](../../game/items/ItemEnchantRuntime.cpp:393) даёт skill bonus; не меняет class cap |
| Учитель | Новое обучение/мастерство | [Party::canMemberLearnSkill](../../game/party/Party.cpp:3606) требует cap != None; [evaluateSkillMasteryTraining](../../game/gameplay/MasteryTeacherDialog.cpp:520) отклоняет rank > cap, затем проверяет навык, численный порог и золото |

**Причина None в исследовании установлена:** это значение в реально запрашиваемой class-таблице,
подтверждённое кодом её разбора, без подходящего расового override. **Причина успешного Expert
в среде пользователя не установлена.** Один старый навык не позволил бы пройти нынешнюю проверку
учителя для класса Minotaur. Факт пользователя сохраняется, но объяснять его сохранением как
доказанным фактом нельзя. Нужны реальные className/raceId, происхождение навыка и hash
установленной class/race table вместе с executable; метаданные Actions не удостоверяют установленный
пакет. Emerald Island относится к сцене теста, не доказывает MM8-класс персонажа.

## 2. Necromancer, Lich и GM

Necromancer и Lich имеют base Master. Естественный Human Necromancer и Undead Lich — также Master.
Продвижение само не даёт GM. Base GM имеют Nosferatu, BountyHunter, RangerLord.
Dragon/GreatWyrm получают GM от race5 add1 к base Master. Формально race5 с другим классом,
у которого base Master, тоже получит GM: это свойство правил, не подтверждение доступности такого
сочетания при обычном создании/найме. Ни превращение в Lich, ни предметный +I сами по себе GM не дают.

Минимальное **предложение**, без применения: одна ячейка `IdentifyMonster × Lich` в
[class_skills.txt](../../assets_dev/engine/data_tables/class_skills.txt) `M → G`.
Necromancer остаётся M; GM становится доступен после продвижения и обучения, а не автоматически.
Изменять всю расу Undead или выдавать GM всем Necromancer не требуется. Нужное решение пользователя:
одобрить ли именно этот cap после продвижения. Учитель, пороги/золото проверяются отдельно.

## 3. Ступени окна характеристик

Вывод прежнего исследования подтверждён. Проверены renderer и оба поставщика actorInspectState:
[renderer](../../game/ui/GameplayPartyOverlayRenderer.cpp:10190),
[indoor](../../game/indoor/IndoorWorldRuntime.cpp:11272),
[outdoor](../../game/outdoor/OutdoorWorldRuntime.cpp:14533).
Ни один из этих путей не принимает результат IdentifyMonster/мастерство как маску скрытых полей.
HP/AC, обе атаки, заклинания и сопротивления формируются без такой проверки. Отсутствие второй
атаки/заклинания или layout — отсутствие данных/элемента, а не другая реализация ступеней.
RMB вызывает resolveIdentifyMonsterSpeech отдельно; его success/fail не управляет окном.

Причина на уровне реализации: данные окна и речевая реакция не соединены контрактом раскрытия.
Почему исторически это было сделано (намеренный выбор либо неполный перенос) исходный код
не доказывает. Не называть это подтверждённым дизайнерским решением.
Описания обещают N HP/AC → E attacks → M spells → GM resistances, но текущий UI показывает всё.
В этой ревизии просмотр сохранён. Восстановление gating потребует отдельного согласования;
оно не является условием реализации нового постоянного знания.

658 — общий mounted реестр MM6/MM7/MM8/custom; первые 198 — исходные MM8 descriptor records,
66 семейств × A/B/C. Это не 198 доказанных встреч и не 658 существ кампании MM8.

Проверены **61 основная сцена** MM8 (map_stats IDs1–61), отдельно прочитаны ещё 10 `_1` сцен:

index1–3 допускает A/B/C при difficulty1–5 и только A при difficulty0; index4–12 фиксирует tier.

[outdoor](../../game/outdoor/OutdoorWorldRuntime.cpp:703).
Проверены также SummonMonsters в обычных map Lua; они не добавили новых ID к выборке.
Табличный encounter slot без точки появления не считается встречей.

Получено **184 разновидности с кампанийным свидетельством**, включая мирных жителей и Fish;
из них 41 имеет готовое размещение, остальные подтверждены допустимыми spawns (множества
пересекаются). Это охват возможных встреч по данным, а не частотная статистика прохождения.
Не утверждается, что все 184 встретятся в одном save: RNG, продвижение сюжета, состояние карты,
условия событий и доступность геометрии могут исключать конкретную встречу. Новые custom/mod
summons, arena и динамическое bolster не расширяют эту базовую выборку задним числом.
Для строгой vanilla-MM8 частотной статистики нужен отдельный оригинальный runtime-прогон;
здесь характеристики берутся из текущих mounted таблиц.

## 5. Покрытие Identify Monster

Ниже **проектная формула знания**, а не текущая речевая реакция:
`power = PL + m*I`, `difficulty = max(0,ML-PL)`; успех `power >= difficulty`,
эквивалентно `ML <= 2*PL+m*I`. m = 1/2/3/4. I>0 и навык изучен обязательны.
Знаменатель 184, одинаковый вес разновидностей, базовый Level без bolster.

## Воспроизведение и вопросы перед реализацией

[final-review.py](final-review.py) читает исходные scene blobs через git show во временную память,
не распаковывает их в игровые assets; [final-review-inputs.csv](final-review-inputs.csv) фиксирует SHA256.
Запуск после базового генератора из [reproduce.md](reproduce.md):
`python3 docs/research/final-review.py` из корня. Нужны локально доступные blobs 61 сцены;
в sparse/partial clone предварительно загрузить их через git show с разрешённой сетью.
Push docs также подходит под paths Windows workflow; коммит имеет `[skip ci]` в теле,
чтобы выполнить запрет запуска сборки без изменения CI. Скрипт не запускает сборку/игру/CI. Он создаёт только аналитические CSV и временную Markdown-таблицу.

Действительно нужны решения пользователя:

1. Принять ли Lich M→GM и какой cap должен быть у MinotaurLord (Expert как у Minotaur либо другой)?
   Факт обучения минотавра из build #3 требует отдельно сверить установленный пакет/персонажа;
   это запрос свидетельств, а не выбор баланса.
2. Утвердить ли категории после визуальной приёмки перечисленных пограничных семейств и политику
   неизвестных/custom шаблонов? До этого GIANT-коэффициент только расчётный.
3. Для нового знания/Death Strike: базовые либо эффективные навыки и Level при bolster;
   работает ли аура не способного действовать специалиста; порядок нового +I относительно
