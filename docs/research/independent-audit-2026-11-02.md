## Подтверждённые проблемы

### A-1. Копия всей партии на каждый кадр в подсказке оружия — Low/Medium

- **Где:** `game/gameplay/GameMechanics.cpp:4518`, вызов из `game/ui/GameplayPartyOverlayRenderer.cpp:6317`.
- **Что:** `buildItemRecoveryInspectSupplement` делает `Party trial = party` для предпросмотра надевания,
  а вызывается из функции отрисовки подсказки, то есть каждый кадр, пока подсказка открыта.
- **Почему проблема:** глубокая копия партии, инвентарей и резерва таверны в цикле отрисовки ради одной строки текста.
- **Когда:** при удержании ПКМ на неэкипированном оружии.
- **Как проверить:** профилировщиком или счётчиком копий при открытой подсказке. Величина просадки не измерена.
- **Исправление:** кешировать строку по `objectDescriptionId`, слоту и участнику, пока подсказка открыта.
  Логику расчёта менять не нужно.
- **Тест:** не обязателен, достаточно замера.

### A-2. В документации мода текущие факты смешаны с устаревшими — Medium (документация)

- **Где:** `docs/MINOTAUR_REBALANCE.md`, раздел «Совместимость и статусы» (навык с ID 40, формат сохранения 95);
  `docs/ROADMAP.md`, раздел «Подтверждённая база: Windows build #3».
- **Что:** действуют ID 49 (`game/party/SkillData.cpp`), формат сохранения мода 143 и база
  `minotaur-1.20-c80ebaa9634d-25-1`. Оба документа были журналами, куда новые записи дописывались сверху,
  поэтому текущего состояния в них не было видно.
- **Когда:** при чтении сверху вниз любым человеком или агентом.
- **Исправление:** **выполнено в этой задаче**: сводка статусов сверху, пометки у устаревших строк, история сохранена.

### A-3. Новые файлы в `docs/` не видны `git status` — Medium (процесс), исправлено

- **Где:** `.gitignore:20-22` игнорирует `/docs/*`, кроме двух файлов. 51 из 65 отслеживаемых файлов `docs/` скрыт
  sparse checkout.
- **Что:** новый документ не появляется в `git status` и не попадёт в коммит без `git add -f`.
  Скрытые документы не находит поиск по рабочему дереву, их можно прочитать только через `git show HEAD:<путь>`.
- **Как проверить:** `git check-ignore -v docs/ROADMAP.en.md`.
- **Исправление:** **выполнено**, правила `/docs/*` убраны из `.gitignore`. Поправка к первому проходу: `git add -f` этого не решал, для путей вне шаблонов sparse нужен `git add --sparse <путь>`. Шаблоны не менялись.
- **Тест:** `tools/check_doc_i18n.py` предупредит, если документы снова начнут игнорироваться.

### A-4. Лич получает иммунитеты Light/Dark вместо Mind/Body — Medium, унаследовано от upstream

- **Где:** `game/party/Party.cpp:1083` (`applyLichState`). Тест `tests/ScriptedMapRegressionTests.cpp:5668` закрепляет

- **Как проверить:** отравляющий удар по личу до и после исправления.
- **Исправление:** решить целевую совместимость, затем отдельное изменение с явной миграцией сохранений (`UND-003`).

## Вероятные проблемы, нужна проверка или решение

### B-1. Механики мода частично действуют в правилах MAW — закрыто, вне рамок мода

- **Где:** `game/gameplay/GameMechanics.cpp` (удалён `halveTargetArmorClass` для GM Axe),
  `game/rules/maw/MawCombatRules.cpp:815` (свой этап `resistance`), `game/party/Party.cpp` (`synchronizeInnateAbilitySpells`).
- **Что:** изменения живут в общем коде. По чтению кода в MAW ×2 для двуручного топора не срабатывает,
  прибавка GM к Recovery перекрывается `characterAttackRecoveryTicks`, эффект снижения AC снят, а Lethal Strike
  и Damage Resistance, похоже, остаются. Текст MAW для GM Axe (`texts.yml:744`) снижения AC не обещает, поэтому
  само снятие регрессией не выглядит.
- **Почему проблема:** баланс мода определён только для Standard, а в MAW получается неописанная смесь.
- **Как проверить:** минотавр в профиле MAW, бой и трассировки `lethal_strike_trace`, `minotaur_damage_trace`.
- **Решение:** MAW не поддерживается, исправление и тест не требуются.

### B-2. Lethal Strike убивает сквозь поднятый энергощит — известное ограничение, Deferred / Low Priority

- **Где:** `game/outdoor/OutdoorWorldRuntime.cpp:17921`, `game/indoor/IndoorWorldRuntime.cpp:16877`.
- **Что:** здоровье обнуляется независимо от результата `applyActorShieldHit`. Контракт называет только защиту
  `canReceiveDamage=false`, про щиты он молчит. В тестах этого сценария нет.
- **Как проверить:** цель с поднятым щитом из `shields.yml`, принудительный успех проверки.
- **Решение:** предполагаемое поведение — не убивать; исправление отложено до практической необходимости, [материалы](../design/lethal-strike-protection-task.md).
- **Тест:** T-4, отложен.

### B-3. Один слот `overflowItem` на несколько предметов — Low

- **Где:** `game/items/AlchemyBenchRuntime.cpp:769,785,793,803`.
- **Что:** если бы переполнились сразу два предмета, второй затёр бы первый и предмет пропал бы. По моему разбору
  сейчас это недостижимо: остаток возвращается на только что освобождённое место. Гарантия держится на неявном условии.
- **Исправление:** `assert` на пустой слот или вектор. **Тест:** не требуется при `assert`.

## Архитектурные риски

- **Русский текст в коде.** `minotaurRussianText` используется в 15 местах, строки зашиты в `GameMechanics.cpp` и рендереры,
  настройка лежит в `[debug]`. Рабочий компромисс: runtime-локализации у этих строк нет. Но текст в слое механик будет
  мешать при слияниях. Если строк станет больше, стоит вынести их в таблицу данных.
- **Стоимость слияний.** Мод меняет `GameMechanics`, `GameplayActionController` и формат сохранений. Таблица
  `saveSchemaVersion` (`game/maps/SaveGame.cpp`) требует новой строки при каждом обновлении upstream. Решение верное, ошибка
  обнаруживается fixture-тестами, но шаг легко забыть, поэтому он внесён в правила.
- **CI выбирает тесты по шаблонам имён.** Новый тест с неподходящим именем молча не попадёт в `minotaur-windows.yml`.
  Предложение: общий префикс `Minotaur:` для тестов мода.

## Что проверено и оказалось в порядке

- **Damage Resistance.** Формула совпадает с описанием, предел соблюдён, применяется только к Physical и один раз.
  Удар в 1 единицу округляется до 0, это прямое следствие утверждённого floor.
- **Порядок ×2 у GM двуручного Axe.** Сначала множитель по типу монстра, затем отделение стихийной части, ×2 только физической
  части, защита от переполнения `int`, и лишь затем сопротивления. Повторного применения нет.
- **Recovery.** Бонус GM один на два топора, только для `Weapon` и melee, минимум 30 тиков. Копий расчёта в UI нет: подсказка
  вызывает ту же функцию и учитывает переопределения правил. Это лучшее решение в моде.
- **Axe + Mace.** Mace справа и Axe слева работают корректно, обратный порядок запрещён. Ошибки нет, поведение теперь описано.
- **Стаки.** Совместимость через сравнение всех полей `InventoryItem`, поэтому свойства не теряются; поле `identified`
  нормализуется только там, где оно не значимо. Перенос транзакционный, цены продажи и покупки считаются за единицу.
- **Lethal Strike.** Вероятности совпадают с контрактом, одна проверка за действие, смерть проходит через обычную ветку гибели монстра.
- **Сохранения.** Разделение заголовков мода и upstream и точное чтение до конца файла, особенно для двух вариантов v85,
  очень надёжны.
- **Levitate и Mind Resistance.** Защита от окружающей среды действует в общем `Party::applyMovementEffects`; своих правок
  Mind Resistance в форке не осталось, используется исправление upstream.
- **Честность отчётов.** Автоматические и ручные проверки разделены, допущения обозначены. Это сильная сторона документов Codex.
