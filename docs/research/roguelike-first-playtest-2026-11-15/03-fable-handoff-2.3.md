## Реальные правила исходной точки

New Game → RULESET Roguelike → континент → создание партии. Рассчитано на четверых;
континент задаёт набор классов/рас/портретов, старт всё равно Goblinwatch. Debug run new создаёт
тестовую партию Knight/Archer/Cleric/Sorcerer и не заменяет пользовательское создание.

Маршрут [tier1,tier2,tier3,tier3]: Goblinwatch; один из Abandoned Temple / Tsantsa / Fist;
два разных из Silver Helm Outpost / Icewind Keep / Monolith / Silver Helm Stronghold.
Seed определяет выбор. На пяти больших картах groupScale0.5 — тестовое число.

Выход заперт до стража. При убийстве более50% исходного суммарного HP появляется сильнейший вид карты
с HP×4 у входа. Есть добровольный перенос ко входу. Убийство стража открывает выход;
при неудачном spawn код открывает его без стража. Вес призванных позднее существ в исходную цель не входит;
скрытые/поздно ставшие враждебными могут менять пересчитанный total — известное ограничение.

Десять повышений:3+3+2+2, каждое всем +4 MM уровня и по выбору одной карты каждому герою.
ИтогL41. Последнее повышение dungeon приходит с вызовом стража. Выбор сейчас из3;
обычно известный skill step, perk и остаточный случайный вариант. Ступени N1/E4/M7/GM10,
потолки класса действуют; персонаж79 (героиня Medusa) игнорирует их. Отдельного класса Medusa нет:
её выбранный обычный класс продолжает задавать HP/SP/стартовые skills.

Пул числовых перков: основные статы+15, HP+30, SP+25, AC+8, resistances+10,
melee/bow damage+4; Explosive arrows использует штатный Carnage-путь и требует Bow.
Магические школы выдают3 книги при изучении и2 при улучшении; книги нужно читать;
повторы известных/имеющихся/должных исключаются, полные рюкзаки создают очередь доставки.
Light/Dark в нынешнем пуле skills нет. Random choices устойчивы к reload.

Старт500gold/2food. После dungeon1–3 код автоматически открывает Camp: пять штатных MM6-домов и Next.
HP/SP живых восстанавливаются бесплатно; states/dead/broken gear остаются. Camp при необходимости
переводит часы к09:00, shops используют штатные ассортимент/цену/членство. Отдельного Rest-пункта нет.
После второго стража — следующее продвижение класса; после последнего выхода — Victory/main menu.
Смерть всей партии завершает run. Формат mod saves180/upstream179; run state в существующих variables.

Реализация сохраняет стандартный бой этой Minotaur-сборки: RoguelikeRules заменяет только Experience
и Monsters, прочие интерфейсы делегирует standardGameRules. Это не отдельная полная боевая система.

## Первый ручной тест — весь результат

Работает по наблюдению игрока: запуск без видимых ошибок; импорт портретов/кукол; импорт и загрузка
старых Minotaur saves; старт Medusa на Nighon; старт run в Goblinwatch; появления/выбор карточек;
книги от магических карт; победа над усиленным Goblin King; магазины Camp после обходной последовательности.
Фиолетовая полоса прогресса понравилась: **сохранить** её внешний вид и полезность.

Баги:

1. **P0:** после Goblin King штатное “Do you wish to leave Goblinwatch?” OK/Close.
   OK визуально ничего; последующий Close открывает Camp. Немедленный Close, по словам игрока,
   вызывает обычный выход. Во второе подземелье попасть не удалось.
2. **P1:** подсказки статов в создании показывают расовую стоимость без игрового смысла,
   в gameplay screen объяснения есть.
3. **P1:** Add Portrait перекрывает элементы выбора портретов.
4. **P1:** гильдии Camp недоступны без членства; обычные shops работают.

Bug screenshots получены и просмотрены в `/home/plane/projects/project-medusa/test_screenshots`:
`Bug_On_The_End_Of_1st_Level_.png` подтверждает штатные Goblinwatch/OK/Close;
`Add_portret_Button_Bug_screen.png` подтверждает overlap Add Portrait с верхним рядом у Chedian/Close.
Первоначальные три снимка инвентаря 11–12 ноября остаются отдельными историческими материалами.
На снимке выхода видны пять героев: проверить фактический ruleset и допустимый размер партии,
включая число карточек и баланс. Расчёты40 выборов относятся к партии из четырёх, не к пяти.
Не считать пятого героя доказанным багом и не ограничивать партию без решения пользователя.
Нет новых проверок dungeon2–4, defeat/victory, полного баланса, всех saves/классов/стандартных кампаний.

## Установленная причина P0 и оставшаяся неопределённость

См.02 §3 для полного доказательства. Цепочка:

1. 6d01.lua event51 задаёт MoveToMap наружу (строки384–386).
2. `GameplayDialogController.cpp` 3346–3427 MapTransitionConfirm создаёт pending move и требует close.
3. `GameplayScreenRuntime.cpp::executeActiveDialogAction` 2514–2560 **откладывает закрытие**
   в m_pendingMapMoveDialogClose до начала map loading.
4. `GameApplication.cpp::processPendingMapMove` 14898 перехватывает move в Camp и возвращается раньше
   `closeTransientGameplayUiForMapMove`/`closeActiveDialogForMapMove` (15154–15181).
5. `holdMapMoveForDungeonRunCamp` 643–682 уже лечит партию, меняет время, ставит CampOpen и сохраняет move;
   игнорирует неуспех открытия Camp.
6. `openDungeonRunChoice` 863–875 запрещает новый диалог, пока exit dialog активен.
7. После ручного Close `updateDungeonRunRules` 1080–1087 повторяет открытие Camp.

Коллизия владения диалогом подтверждена кодом и объясняет OK→Close→Camp.
Entered на этом раннем шаге ещё не увеличен, но внутреннее состояние Camp и ресурсы уже изменены.
Поведение немедленного Close и невозможность продолжить из уже открытого Camp нуждаются в отдельном
runtime trace; не выдавай их за полностью доказанные следствия единственного дефекта.

Минимальный путь: корректно завершить отложенный departure dialog до ruleset-Camp, не терять pending move,
не оставлять callback старого окна способным закрыть новое. Проверять успех открытия.
Отдельный риск: redirect увеличивает entered/сбрасывает guardian до успешной загрузки;
нужен commit-on-success или явный rollback, негативный тест. Сгенерированный map Lua не редактировать.

## Решения по дизайну, которые остаются открыты

В02 §8 предложены три направления: mastery + несколько меняющих бой перков; mastery + теги синергии;
поздние мощные развилки. Все сохраняют MM, E/M/GM, случайность и сопротивления. Первое дешевле и понятнее,
второе разнообразнее, но сложнее контролировать proc loops; третье даёт кульминацию, но нуждается в защите
от бесполезных финальных предложений. Ни одно пока не выбрано.

Исходный бюджет —10 карт на героя: два GM с нуля занимают8, с двух стартовых N —6.
Четыре предложения увеличат доступность нужных сочетаний, но не число выбранных усилений.
Не гарантировать несколько GM и много сильных перков без проверки бюджета.

Предварительный gold budget из02:1500/3000/5000/7500 **на партию**, не утверждённые значения.
Первые три ориентируются на две покупки value≈500/600/1000 при multipliers1.5/2.5/2.5;
это расчёт цели, не замер магазинного stock. Последняя сумма условна: после финала тратить негде.
Нужен замер обычной добычи и продаж; ранний Artifact может сильно перевесить эту экономику.

## Сохранения, baseline и updater

Срочный риск перед редизайном: уровни перков записаны по **индексу** YAML (`0xF100+index`),
а прибавки уже внесены в героя. Переставить/удалить карты без миграции нельзя. Решить stable ids,
версию run rules и судьбу незавершённых runs. Контейнер save не менялся — семантика может измениться.
При upstream save bump — новая saveSchemaVersion mapping и frozen fixture production save,
независимый review save/inventory/боевых формул согласно AGENTS.

Baseline кода уже в da1bb162, не нужен пустой commit. С отдельным разрешением сохранить original package,
SHA256, CI metadata/index/content ids, configure flags, Medusa receipts, saves и logs;
tag исходного прототипа указывает на da1bb162, commit отчёта — отдельная вещь.
Прототип обозначать first-playtest/alpha с блокером перехода, последующие версии — итерациями.

Штатные `engine/update`, `game/launcher`, `GameUpdater`, `ContentSetup`, publisher уже реализуют
versioned app/current, signatures, incremental packs и activation/rollback. Переиспользовать их.
Нужен свой подписанный mod channel/URL/trusted keys; штатный upstream channel включать нельзя —
он способен заменить mod files. Смена URL без собственных keys недостаточна.
Сейчас offline Apply-MinotaurUpdate проверяет base/hashes и сохраняет user data; новый full da1bb
ещё не выбран в latest-baseline.json (там1.21). Новую baseline надо получить из фактической CI metadata.
Обсудить hosting/канал; затем staging/bootstrap и естественный UI обновления, без ручного скрипта каждый раз.

Режим изолировать через package/RoguelikeRules и shared hooks, не ветвить весь бой/внутренний мир.
Новые награды exactly once, очередь при полном рюкзаке, deterministic seed, found rare tracking.
Обычные Standard/MAW/Medusa saves и обычные guild/exit должны остаться прежними.

## Рекомендуемый порядок и приёмка

1. Снять immutable baseline и воспроизвести **настоящую дверь**, без run leave/run pick.
2. Исправить ownership/close и ошибку загрузки с rollback; изолированный runtime regression.
3. Согласовать меню/Rest, затем Camp/guild access и интерфейсные дефекты.
4. Ввести4 предложения и save policy/stable perk identity до удаления старых карт.
5. Согласовать модель перков и boss reward economy, реализовать с focused tests и независимым review
   для боя, inventory и миграций. Сохранить полосу прогресса.
6. Полный повторный Windows playtest всех4 dungeon, экономика по нескольким seed;
   затем RU/EN actual-rules docs и отдельная задача подписанного updater.

- Goblinwatch до/после стража; настоящий OK закрывает exit и открывает правильное меню без второго Close.
  Close/Escape без OK отменяют ожидаемое действие без утечки pending move; повторный клик не дублирует переход.

- Ошибка загрузки stop2 не меняет run index и guardian; autosave on/off, save/load до двери,
  с живым/мёртвым стражем, в Camp и при полных рюкзаках; старые saves по выбранной политике.
- Guild показывает и исполняет нужные услуги в run, обычная кампания по-прежнему требует membership.
- Карты4 уникальны, достижимы и подходят caps; при исчерпании меньше4 без дублей;
