# Инкрементальные ZIP-обновления Minotaur

Исследовано2026-10-23: официальный v1.10 (`3f06332001c7a841cc2c2d161f192a1252b25713`)
и upstream/main `7fdb256677107876e40c5050b0d9522efb834bb9`.
Переход уже присутствует в коде нашего мода; проблема была в выпуске полного ZIP каждый раз.
Изменения main после1.10 не меняют изученные updater/packaging-механизмы и не интегрируются этой задачей.

## Как устроен оригинал

- [Releases](../../packaging/RELEASE.md), [план/реализация](../../packaging/UPDATER_PLAN.md).
- `tools/runtime_packs.py`: детерминированные архивы по доменам и корзинам, `content_id`
  от имён/размеров/SHA256 содержимого, отдельно SHA256/размер физического ZIP.
- `packaging/publish_release.py`: переиспользование пакетов с тем же content_id/package/mount,
  отдельный небольшой архив программы. Это не побайтовый diff исполняемого файла.
- `engine/update/AppUpdater.cpp`: сравнение содержимого, скачивание нужного, проверка SHA256.
- `engine/update/AppInstallation.cpp`: новая программа в `app/<version>`, общий `assets/packs`,
  атомарное переключение `app/current`; данные пользователя находятся вне версионного каталога.
- Launcher откатывается на `app/previous` после двух неудачных стартов. После первого успешного
  старта движок удаляет предыдущие версии/неиспользуемые пакеты и обновляет root launcher
  из `OpenYAMM-launcher.exe` новой версии. Это ограниченный аварийный откат, не вечный архив.
- Онлайн-оригинал использует подписанные каналы/сервер автора. Его адрес/ключи нельзя использовать
  как канал мода: такая загрузка заменит мод обычным OpenYAMM и потеряет его загрузчик сейвов.

## Решение пользователя

Выбран ZIP-патч поверх установленного мода. Отдельный онлайн-канал не входит в задачу.
Баланс, игровой код, формат сейвов95 и прежние исправления не меняются.

Патч содержит всю небольшую программу и только изменившиеся пакеты ресурсов. Установщик Windows
проверяет базу и файлы, подготавливает новый app-каталог и переключает версию последним действием.
`saves`, `settings.ini`, логи и прочие пользовательские файлы не включаются в payload.
Каждая сборка получает уникальное имя app-каталога; прежний каталог не перезаписывается.

Переиспользование определяется по id/package/mount/content_id. Если новая версия компрессора
создала иной ZIP с тем же содержимым, сохраняются имеющиеся файл/размер/SHA256 из установленного
индекса. Это предотвращает загрузку5ГБ из-за перекомпрессии. Последующие патчи сопоставляют
логическое содержимое, поэтому работают после полного ZIP и после предыдущего патча.
При коллизии физического имени с иными байтами старый архив не перезаписывается.

## Проверки реализации

Выполнены: сравнение программного/ресурсного обновления, отсутствие неизменных пакетов в ZIP,
варианты компрессии, цепочка патчей, правильная база, повреждённые файлы, безопасные пути,
повторный запуск и сохранность пользовательских данных. Установщик проверяется именно
Windows PowerShell5.1 на GitHub Actions. Статусы результатов обновляются после выполнения.

## Реализация

[Генератор](../../tools/minotaur_updates.py), [bootstrap индекса](../../tools/fetch_minotaur_baseline.py),
[установщик](../../packaging/minotaur/Apply-MinotaurUpdate.ps1),
[workflow](../../.github/workflows/minotaur-windows.yml). Локальные7 Python-тестов passed;
8 Windows PowerShell5.1 сценариев прошли в финальном run40000571371.
Отдельный tests_only прогон проверяет установщик без дорогостоящей пересборки игры.

Первый Windows-only run39960808276:5 положительных сценариев остановились на отсутствии
Get-FileHash в дочернем5.1 окружении. Проверка переписана на .NET SHA256/поток с Dispose;
не требуется импорт модуля или изменение системного PSModulePath. Защитные сценарии
отказали до переключения; окончательные результаты — после повторного прогона.

В повторе39961282682 хеширование заработало; переключение остановилось на File.Replace с
пустым backup-путём. Теперь используется явный уникальный backup в той же папке, удаляемый
после успешной атомарной замены. В CI нормализован только PSModulePath дочернего5.1 процесса
(родитель — PowerShell7); системная конфигурация пользователя не меняется.
