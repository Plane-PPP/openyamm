# MM8: инвентаризация монстров

Уточнение 2026-10-15: [финальная ревизия](final-review.md) отделяет
198 исходных descriptor records от 184 разновидностей с кампанийными свидетельствами,
уточняет caps/UI, корреляции и вопросы визуальной классификации. Прежние расчёты по 198
сохранены как инвентарный baseline; они не являются статистикой частоты встреч.


Статус: **Research**. Назначение: воспроизводимые исходные данные для Death Strike,
Identify Monster и бестиария. Срез: 2026-10-14, исходный commit
`142a54e01da50d9faf258e38919e88dba9e8de29`. Игровые данные не изменялись.
Этапы [ROADMAP](../ROADMAP.md#этапы-разработки): R1, R2, R6.

## Источники и границы выборки

- [monster_data.txt](../../assets_dev/engine/data_tables/monster_data.txt): **658** строк шаблонов
  объединённой базы MM6/MM7/MM8/custom. Максимальный ID не равен количеству строк: имеются пропуски.
- [monster_descriptors.txt](../../assets_dev/engine/data_tables/monster_descriptors.txt): геометрия,
  имена спрайтов, звук и параметры preview; соединение по ID.
- [bolster_monsters.txt](../../assets_dev/engine/data_tables/bolster_monsters.txt): Type, ExtraType,
  Creed и параметры потенциального усиления. Type не является готовой категорией GIANT.
- Оригинальный [MM8 dmonlist.bin](../../assets_dev/worlds/mm8/_legacy/bin_tables/dmonlist.bin)
  прочитан из Git object через `git show HEAD:assets_dev/worlds/mm8/_legacy/bin_tables/dmonlist.bin`.
  В sparse checkout файла может не быть. **198** записей, 184 байта/запись после 4-байтового счётчика.
  Все 198 имён совпадают с дескрипторами активной таблицы по ID, без учёта регистра.
  Таким образом, нативный блок MM8 — **1–198**, **66 групп по три варианта A/B/C**.
  Это группировка по Picture/InternalName, а не по одинаковому display name.
- [MonsterTable.h](../../game/tables/MonsterTable.h),
  [MonsterTable.cpp](../../game/tables/MonsterTable.cpp): реальные поля и правила загрузки.
  `parseMonsterResistanceValue`: Imm → 200; сопротивление ≥200 означает иммунитет в
  `GameMechanics::resolveMonsterIncomingDamage`.
- [monster_portraits.txt](../../assets_dev/engine/data_tables/monster_portraits.txt),
  [monster_projectiles.txt](../../assets_dev/engine/data_tables/monster_projectiles.txt),
  [monster_death_drops.txt](../../assets_dev/engine/data_tables/monster_death_drops.txt),
  [hostile.txt](../../assets_dev/engine/data_tables/hostile.txt): связанные таблицы отображения,
  снарядов, дополнительной добычи и отношений. Не являются дополнительными шаблонами характеристик.

**Не заявляется сверка базовых Level/HP/AC с отдельной vanilla MONSTERS.txt**: её нет в доступном
срезе MM8. Числа ниже — реальные активные таблицы OpenYAMM для нативных MM8-дескрипторов,
без runtime bolster. Оригинальная бинарная таблица доказывает принадлежность и исходную геометрию,
но не содержит HP/Level. Карты и все уникальные экземпляры не присутствуют в sparse checkout;
инвентаризация не означает, что каждый шаблон встречается в текущем прохождении.

## CSV и смысл полей

[monster-stats.csv](monster-stats.csv) содержит все **658** шаблонов, включая отдельно помеченные
`scope=MM8-original-descriptor` и `merged-other-or-custom`. Сохранены все 39 исходных колонок
monster_data, все 22 колонки descriptor, все 17 колонок bolster, численные сопротивления,
битовая маска runtime kind flags и предварительная размерная категория.

- `full_hp` — базовое полное здоровье шаблона (`MonsterStatsEntry::hitPoints`), не текущее HP экземпляра.
- `*_resistance_raw` сохраняет Imm; численные `*_resistance` воспроизводят загрузчик.
- `immune_damage_types` перечисляет иммунитеты к типам **урона**, не общий иммунитет к смерти/контролю.
- `special_attack_raw`, `attack*_damage`, `spell*_raw` сохраняют исходные токены и dice-формулы.
  Разбор спецэффектов: `parseMonsterSpecialAttack`; Dead есть в enum и не является иммунитетом цели.
- `special_column_raw` сохраняется для аудита: последняя Special-колонка не загружается как
  отдельное поле `MonsterStatsEntry` в текущем `loadStatsFromRows`.
- `runtime_kind_flags`/`mask`: Undead=1, Dragon=2, Swimmer=4, Immobile=8, Peasant=16,
  NoArena=32, Ogre=64, Elemental=128, Titan=256, NoCorpse=512, Demon=1024, Elf=2048.
  Они выводятся из распознаваемых Type/ExtraType; произвольный текст Type не превращается в флаг.
- `proposed_key` — **предложенный**, пока не зарегистрированный namespaced ID. Не путать с
  runtime actor index и не считать действующей гарантией стабильности сохранений.
- `original_*` — геометрия MM8 из бинарника; пусто для других миров, а не «ноль».
  `height/radius/to_hit_radius` — активная геометрия OpenYAMM. Размеры в единицах движка, не метрах.
- `category_proposed` — проектная классификация, не игровой флаг; `category_review` фиксирует
  необходимость проверки. [Подробная классификация](monster-size-classification.md).

## Шаблон и экземпляр

У экземпляра есть отдельные текущие HP, позиция, actor index, уникальное имя/группа, AI state,
атрибуты, состояния смерти/контроля, Shrink, усиленные характеристики и кэш bolster.
[IndoorWorldRuntime::actorInspectState](../../game/indoor/IndoorWorldRuntime.cpp) возвращает
runtime maxHp и AC; [OutdoorWorldRuntime](../../game/outdoor/OutdoorWorldRuntime.cpp) имеет
соответствующий путь. [GameplayBolsterRuntime](../../game/gameplay/GameplayBolsterRuntime.cpp)
может менять HP, AC, атаки, заклинания и награды.

Для GIANT проверять `2 * currentHp < runtimeMaxHp` **после текущего обычного удара**,
не сравнивать с CSV full_hp. Размерную категорию предлагается закреплять за шаблоном и
не менять вследствие Shrink. Нужно ещё определить, использовать ли базовый Level или эффективный
runtime Level для Death Strike; базовый Level принят только в аналитических CSV.

## Статистика нативного блока MM8

Все варианты, включая крестьян и School of Fish: N=198. Это не выборка только агрессивных врагов.

| Показатель | Значение |
| --- | --- |
| Level min / max | 1 / 125 |
| HP min / max / median | 3 / 1937 / 153 |
| Pearson(Level, HP) | 0.970148 |
| Pearson(Height, Level) / Pearson(Height, HP) | 0.301679 / 0.294734 |
| Pearson(Radius, Level) / Pearson(Radius, HP) | 0.395641 / 0.371944 |

152/198 шаблонов имеют Height=160. Высота и радиус плохо отделяют высокоуровневых существ:
Ruby Dragon имеет Level125/HP1937, но Height160/Radius120. Напротив, Wasp Warrior имеет
Height220 и не должен автоматически считаться гигантом. Корреляция не определяет категорию.
Зависимость HP от Level очень сильная; это не доказательство размера и не независимые признаки.

## Изменения геометрии относительно MM8-бинарника

Height/Radius отличаются у **21** разновидности: Ogre Warrior 31–33 (R100→90), Dragon 70–72
(R300→200), Dire Wolf 85–87 (R150→100), Ogre Mage 106–108 (R100→90), Juggernaut 157–159
(R175→120), Naga 169–171 (R135→90), Wimpy Dragon 190–192 (H500→300, R500→300).
Все 198 имеют отличающийся ToHitRadius: активная таблица задаёт 0; исходное значение сохранено в CSV.
Никаких изменений геометрии в рамках исследования не сделано.

  уже достаточны для реализации под действующие таблицы OpenYAMM.
- Визуально просмотреть пограничные семейства и масштабы в реальных сценах: artwork не смонтирован
  в доступном sparse checkout, из имён спрайтов внешний вид не считается проверенным.
- Зафиксировать runtime Level/MaxHP при bolster, уникальных боссах, summoned actors и reanimation.
- Не переносить NoCorpse, Undead или иммунитет к Body автоматически в запрет Death Strike.
