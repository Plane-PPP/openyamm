# Пример: кукла героини Project Medusa

Первый персонаж, на котором проверен метод (2026-11-18). Лицо — 56 кадров по ТЗ портретов v2 проекта Medusa
(`Plane-PPP/project-medusa`, `docs/design/portrait-generation-brief-v2.md`), кукла — по `doll-brief-v3.md` отсюда.

| Файл | Что |
|---|---|
| `doll-brief-v3.md` | ТЗ куклы Медузы: почему не удались попытки B–D, перенос метода автора на тело `pc02bod`, промпт, проверка, раздел 12 — одежда |
| `doll_graft.py` | скрипт Codex после исправлений прогона на `pc04` (рост по тёмному, верхняя область кожи); им собран пак `medusa_pc04` (g2, сила тона 0,65), проверенный в игре 2026-11-19. Пути и донор зашиты под Медузу (флаг `--pc04`) — образец для `tools/portrait_pack/doll_graft.py`, не для запуска |

Итог: голова резкая, почти анфас, размера головы донора, волосы на месте волос донора; тело и руки `pc02` без
изменений.

Второй прогон, на теле `pc04` (зелёный костюм, раздел 12 ТЗ), показал две ошибки сборки, а не генерации. Обе исправлены в
[`doll.md`](../doll.md), раздел 4:
- каштановые пряди донора вернулись на левое плечо: в сырых генерациях там тёмно-зелёные волосы, но маска разницы
  сравнивает яркость и сочла их равными тёмно-каштановым. Порог 30 вместо 40, найденный на `pc02`, остался в
  `graft.json` того прогона и в `pc04` не перешёл, да и не помог бы (разница < 30 у 70–80 % этих пикселей). Решение —
  рост зоны головы по тёмному;
- маска кожи взяла самую большую область — грудь под чокером, — и сила тона не меняла лицо. Решение — самая верхняя
  область.

После пересборки без новой генерации пак `medusa_pc04` (`base_character: 4`) проверен в игре 2026-11-19: всё в
порядке. Пак `medusa_portrait_doll_graft` собран, пользователь принял результат. Рабочие файлы — в игнорируемой
`output/portrait-doll-project-medusa/` checkout'а `openyamm-minotaur-v2.3` (в git не входят).
