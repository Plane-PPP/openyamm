# Пак портрета и куклы по картинке — ТЗ для Codex

Версия 1, 2026-11-18. Codex по картинке, фото или описанию персонажа делает пак для кнопки **Add Portrait...** при
создании партии: 56 кадров лица и куклу (тело с головой персонажа). Метод проверен на героине Project Medusa: лицо
(ТЗ портретов v2) работает в игре, кукла (`medusa-case/doll-brief-v3.md`) собрана и принята пользователем.

| Файл | Что |
|---|---|
| `README.md` (этот) | порядок работы, остановки, правила |
| [`faces.md`](faces.md) | лицо: геометрия, промпты, таблица 56 кадров, проверка |
| [`doll.md`](doll.md) | кукла: пересадка головы на тело донора, промпт, проверка, исправления |
| [`dolls.md`](dolls.md) | каталог базовых персонажей (тел) для вопроса пользователю |
| `upstream-reference/` | материалы автора OpenYAMM: метод кукол MM9, уроки генерации в Codex |
| `medusa-case/` | удачный пример: ТЗ куклы Медузы и скрипт, которым она собрана |
| `tools/portrait_pack/portrait_kit.py` | сборка кадров лица в окно и проверка набора |
| `tools/portrait_pack/doll_graft.py` | пересадка головы на тело (пишется на этапе 0) |
| `tools/make_portrait_package.py` | упаковщик пака для импорта |
| `devdocs/CUSTOM_PORTRAITS.md` | формат пака и что проверяет импорт в игре |

## 1. Результат

Папка и zip пака: `portrait.yml` (`id`, `name`, `base_character`), `01.png … 56.png` 118×158 RGBA, `doll/body.png`
размера тела базовой строки. Импорт игры (`game/party/CustomPortraits.cpp`) принимает такой пак: кадры 118×158 8-bit
RGBA, тело ровно вдвое больше логического размера тела базы, каждый файл ≤ 1 МБ, руки необязательны. Портрет
предлагается при создании партии там же, где его базовая строка (раса, классы, мир).

## 3. Правила для Codex

1. Писать только в `$PACKS/<id>/` и `$PACKS/_cache/`; в репозитории — только на этапе 0 (`tools/portrait_pack/`).
   Ничего не коммитить без слова пользователя.
2. Пиксели меняют только `portrait_kit.py` и `doll_graft.py`. **Запрещено:** размытие, уменьшение-увеличение,
   рисование полигонами или кистью, ретушь генераций, правка тела донора ниже шва, правка рук.
3. Генерация — встроенным инструментом Codex: **один вызов — один кандидат или кадр**, промпт из шаблонов `faces.md` и
   `doll.md` с подстановками из `card.yml`, вложения ровно как указано (не больше пяти). Ответ сохранить без изменений
   и записать в журнал (`prompts.jsonl`, `runs.json`).
4. Корректирующая перегенерация — одна на кадр или кандидата и только при сломанном кадре или прозрачности; первый
   ответ сохраняется как `_rejected`. Самоотчёту генератора о прозрачности не верить — проверять альфу.
5. Не получается шаг (ошибка инструмента, пустая маска, регистрация не сходится) — остановиться и написать, что и
   почему. Обходов не изобретать.
6. Старые попытки не перезаписывать: новые продолжают нумерацию. Исправление — одна правка за раунд по таблицам
   `faces.md` (раздел 6) и `doll.md` (раздел 6), запись в `changes.md`. Прежде чем генерировать заново, проверить
   сырую генерацию: если дефекта в ней нет, виновата сборка, и чинится скрипт. Правка, которая помогла, переносится в
   значения по умолчанию инструмента и в справочник (`faces.md`, `doll.md`, `dolls.md`), а не остаётся в настройках
   одного прогона.
7. Скрипты — через `safe-heavy-run run --profile light -- $PACKS/_venv/bin/python …`; для `qa` всего набора, если
   light (512 МиБ) не хватит, — без `--profile`. Лимиты не повышать (`/home/plane/AGENTS.md`).

## 5. Порядок для персонажа

Сессию запускать в `$PACKS` (`cd /home/plane/projects/portrait-packs && codex`): все записи — там, ТЗ и инструменты
читаются из `$REPO`. Один персонаж — одна сессия; раунд исправлений куклы — новая сессия.

### Этап A. Вход и карточка

Пользователь даёт: картинку, фото или несколько, и/или описание; имя; по желанию `id`, пол, расу, строку куклы
(тогда остановка 2 пропускается) и пожелания к костюму.

Codex: создаёт `$PACKS/<id>/` (`id` — 1–32 символа `a-z 0-9 _`; имя ≤ 48 символов), копирует входы в `input/` и пишет
`card.yml`:

```yaml
id: medusa
name: Medusa
sex: female            # female | male — задаёт образцы и тип куклы
race_look: human       # human | elf | dark elf | dwarf | goblin | vampire | minotaur | troll
source: picture        # photo | picture | description
age: about 25
look: …                # общий облик
face: …
eyes: …
brows: …
nose: …
lips: …
skin: …                # словами и примерный hex
hair: …                # цвет, длина относительно челюсти и плеч, пробор, чёлка
marks: …               # у несимметричных — сторона «своя», «never mirrored»
head_accessories: none
negatives: []          # что генератор склонен добавлять, а нельзя
```

Из карточки собирается CHARACTER LOCK (`faces.md`, раздел 3). Без картинки (только описание) у промпта M нет первого
вложения и строки о нём.

### Этап B. Мастер лица — **остановка 1**

`faces.md`, раздел 4: четыре кандидата → `face/candidates/masters.png`. Сообщение пользователю: лист, карточка
коротко, что заметно у каждого кандидата. Ответ — номер кандидата или замечания. После замечаний: одна правка карточки
или промпта, новые четыре кандидата (нумерация продолжается); два раунда без выбора — показать всё и ждать решения.

### Этап C. Остальные 55 кадров

`faces.md`, разделы 5–7: ракурсы, выражения, позы, `qa` (FAIL 0), `face/review.md`. Без остановки. Это 70–90 вызовов
генератора; при перегрузке генератора — пауза и повтор, не смена промпта.

### Этап D. Выбор куклы — **остановка 2** (пропускается, если строка уже названа)

По [каталогу](dolls.md): строки того же пола и типа куклы, расы персонажа; три рекомендации по правилам каталога с
причиной; `doll_graft.py fetch-row` для них и `catalog-sheet` → `doll/catalog.png` (тела рядом, подписи — строка и
коротко костюм). Сообщение:

```text
Лицо готово: face/final/qa/sheet-game-size.png, анимации face/final/qa/anim-*.gif.
Для куклы подходят N тел (<пол>, <раса>). Рекомендую:
1. Строка 4 (pc04): длинные тёмные волосы, светлая кожа; зелёный лиф и легинсы, перчатки. Пересадка проверена автором.
2. …
3. …
Все подходящие — doll/catalog.png и таблица ниже. Что даёт строка: раса, поза и руки куклы; класс и голос меняются
при создании партии.
Ответьте номером строки; можно добавить «перекрасить ткань в <цвет>» или «без куклы».
```

### Этап E. Кукла

`doll.md`: `graft.json` под донора → `prepare` (посмотреть `seams.png`) → три кандидата → `extract` → `qa` → выбор
кандидата и силы тона по разделу 5. Перекраска — по разделу 7, если пользователь попросил. Без остановки.

### Этап F. Пак

```sh
python3 $REPO/tools/make_portrait_package.py $PACKS/<id>/face/final --id <id> --name "<имя>" \
  --base-character <строка> --doll $PACKS/<id>/doll/package-doll \
  --output $PACKS/<id>/package/<id> --zip
```

`face/final` — кадры 944×1264, упаковщик сам уменьшает их до 118×158 и убирает ключевые цвета. В `package-doll/` — только
`body.png`. Без куклы — без `--doll`.

Проверка пака скриптом: `portrait.yml` (id, name, base_character); 56 кадров 118×158, PNG с глубиной 8 и типом цвета 6
(RGBA); `doll/` — только `body.png`, размер равен телу донора; каждый файл ≤ 1 МБ; zip на месте.

Итоговое сообщение пользователю: где папка и zip; как импортировать (**Add Portrait...** → папка `package/<id>`; zip —
распаковать); что даёт базовая строка; лист `doll/qa/heads-x4.png` и `dolls-x2.png`; чем заменить куклу без генерации
(`doll_graft.py package g2 s100` — другой кандидат или тон); повторный импорт того же `id` виден после перезапуска игры;
для фото — напоминание о распространении.

## 6. Модель и усилие

Основная модель Codex (не mini), усилие **high**: и на этапе 0, и на персонажа. Качество картинок от усилия не
зависит — их рисует отдельный генератор; от модели зависит, насколько точно соблюдаются правила раздела 3.

## 7. Скилл

ТЗ можно оформить скиллом Codex (папка скилла с `SKILL.md`; куда класть, Codex знает сам). `SKILL.md` — разделы 2, 3, 5
этого файла и шапка:

```yaml
---
name: openyamm-portrait-pack
description: Make an OpenYAMM custom portrait pack (56 face frames and a paperdoll body) from a picture, photo or
  description, for the in-game Add Portrait importer. Use when the user asks for a new party portrait or doll.
---
```

`faces.md`, `doll.md`, `dolls.md` — справочники скилла (ссылками на `$REPO/docs/portrait-pack/` или копиями), скрипты —
`$REPO/tools/portrait_pack/`. Пути `$REPO` и `$PACKS` записать в скилл явно.

## 8. Готово, когда

- Этап 0: инструменты в `tools/portrait_pack/`, проверка на Медузе пройдена.
- Персонаж: `face` — `qa` FAIL 0 и `review.md`; `doll` — выбранный кандидат без FAIL, `review.md`; пак собран и проверен
  скриптом; пользователь получил итоговое сообщение. Проверка в игре — за пользователем.
