## Уже реализованное физическое сопротивление

Для базового уровня персонажа L:

- Minotaur: `R = min(30, 5 + floor(L / 5))` процентов.
- MinotaurLord: `R = min(30, 5 + floor(L / 5) + 7)` процентов.
- Остальные классы: R = 0.
- После способности: `D_after = floor(max(0, D_before) × (100 − R) / 100)`.
- Предотвращённый урон: `D_before − D_after`; округление входит в эту разницу.

| Класс | Уровень 20 | Уровень 50 |
|---|---:|---:|
| Minotaur | 9% | 15% |
| MinotaurLord | 16% | 22% |

Повышение опыта без тренировки не меняет R. Временный модификатор уровня не используется.
Продвижение добавляет 7 процентных пунктов до общего потолка 30%.
Это проектный баланс, уже реализованный коммитом
`6b87339d57c9c484f92820ec5c2606598681da9d`; он не изменяется в текущем этапе.

Порядок подтверждён `GameMechanics::resolveCharacterIncomingDamage` и общим combat controller:
защита от снарядов → предметный множитель входящего физического урона → проверки иммунитетов
и сопротивления/удачи → Master Plate (половина) либо GM Chain (две трети) → пассивное сопротивление
минотавра → применение к HP. Промежуточные целочисленные округления сохраняются.
Пассивная способность не применяется к заклинаниям других типов, падениям или прямым изменениям HP,
которые обходят этот путь. Физические melee/projectile/party-wide попадания используют общий расчёт.

## Диагностика сопротивления

```text
config set minotaur_damage_trace true
config get minotaur_damage_trace
config set minotaur_damage_trace false
```

Настройка: `[debug] minotaur_damage_trace=false` по умолчанию в `settings.ini`.
Файл: `logs/combat_trace.log` относительно рабочего каталога; путь меняется через
`[logging] combat_trace_file`. Общий `combat_trace` включать не требуется.
Сохраняйте `combat_trace_append=true`, чтобы переключение настроек не стирало предыдущую запись.
В консоль попадания не печатаются.

`minotaur_damage` содержит имя/класс/уровень, источник и тип атаки, `before_passive`,
`passive_percent`, `passive_prevented`, `after_passive`, `final_damage`, `hp_damage`, `applied`.
`passive_reached=false` означает, что ранний выход обошёл пассивную способность;
предотвращённый ею урон тогда нулевой. При debug immortality рассчитанный урон и потеря HP различаются.
Промахи и уклонения не являются попаданиями и не записываются этим каналом.

Это результаты предыдущего этапа, не свидетельство ручной проверки в игре или Windows-сборки.

## Подготовка тестовых персонажей

Используйте отдельное тестовое сохранение. `player add Minotaur Test` создаёт персонажа уровня 1,
если партия не заполнена. `goto` принимает числовой ID карты, а не имя файла.
На карте 1 (`goto 1`, дождаться загрузки) `event 167` даёт каждому члену партии 100000 XP за вызов.
Он также меняет квест освобождения Shalwend и добавляет золото: это не нейтральный XP-редактор.
Для уровня 20 нужны суммарно 190000 XP, для 50 — 1225000 XP.

Для тренировки: `gold set 1000000`, `goto 6`, затем Assassin's School (`event 187` на карте 6).
Выбрать минотавра и тренировать до нужного уровня; лимит этого зала — 200.
Для продвижения на карте 1: `qbit set 1545`, `event 740`. Флаг сам по себе класс не меняет.
Для очков навыков выбрать портрет, на карте 1 повторять `qbit clear 268`, `event 497`:
это +2 очка при базовой Luck ≥13. `event 102` повышает базовую удачу на 2 до порога 16.
При Luck ≥20: `qbit clear 269`, `event 498` даёт +5 очков.
Локальные события имеют приоритет над глобальными; ID действуют в указанном контексте карты.

Новая debug-сессия с `[debug] preseed_party=true`, `party_seed_roster_id=29`,
`[startup] start_in_main_menu=false`, пустым `save_file` содержит Ulbrecht во втором слоте:
MinotaurLord, уровень 50, XP 1225000, Axe GM10, Plate Master7, свободных очков 0.
ID 5 даёт Arius (Minotaur5), 13 — Thanys (Minotaur15), 21 — Rionel (MinotaurLord30).
Это не изменение уже загруженного сохранения. Готового минотавра уровня 20 в roster нет.
Уровень навыка повышается очками, мастерство приобретается у учителей отдельно.
Для Master/GM обычно нужны ранг 7/10 и предыдущая ступень; дополнительные требования зависят от навыка.

## Реализованный Axe

Это принятые балансные решения мода, реализованные в общих механиках OpenYAMM:

| Ступень | Поведение |
|---|---|
| Normal | Существующий бонус атаки Axe сохраняется. |
| Expert | Существующее снижение Recovery на эффективный уровень навыка ведущего оружия сохраняется. |
| Master | Существующий бонус физического урона Axe сохраняется; одноручный топор разрешён в off-hand. |
| Grandmaster, одноручный | Дополнительное −Axe Recovery за одно melee-действие. |
| Grandmaster, двуручный | Гарантированное ×2 полной физической части удара по противнику. |

Старый GM Axe в этом форке при успешной процентной проверке уровня навыка устанавливал
`halveTargetArmorClass`: временно половинил AC цели на `Axe × 60` секунд.
Новый GM полностью заменяет этот эффект. Предметные эффекты изменения AC, Sword/Dagger/Mace
и их собственные проверки не изменены. Новая специализация не делает дополнительного RNG-броска.

### Две руки и экипировка

Одноручный топор (`equipStat=Weapon`) разрешён слева с Master Axe, так же как Sword с Master
и Dagger с Expert. До Master запрос левой руки использует обычный вариант основной руки;
он не даёт скрытого разрешения off-hand. Двуручный топор (`Weapon2`) остаётся оружием основной руки.
Двуручное оружие исключает оружие во второй руке, прежние требования навыков/классов сохраняются.

Axe+Axe, Axe+Sword и Axe+Dagger разрешены в обоих порядках при нужном мастерстве каждого
оружия слева. Экипировка хранится в существующих слотах; формат сохранения не изменяется.
Классовые/расовые потолки сохранены: Minotaur (race 3) имеет Axe до Master, MinotaurLord — до GM.
Sword у обоих ограничен Expert, Dagger доступен с Expert. Поэтому обычный минотавр может
держать Sword справа и Master Axe слева, но Axe справа + Sword слева требует недоступного
ему Master Sword. Общая матрица обоих порядков тестируется с заданными допустимыми мастерствами,
а не через повышение классовых потолков.
Для ручной проверки перетащить оружие на соответствующую половину куклы персонажа,
сохранить, загрузить и проверить обе руки и характеристики.

### Recovery

Движок использует для двух оружий более медленное **базовое** Recovery, до применения бонусов.
Основная рука выигрывает при равенстве. Базы: Axe 100, Sword 90, Dagger 60 ticks.
Поэтому Axe ведёт Recovery в перечисленных смешанных парах независимо от порядка рук.
Expert-бонус берётся только от выбранного ведущего оружия, не от обеих рук.

Для melee:

```text
R_before_GM = base_weapon + shield_penalty + armor_penalty
              − Speed_bonus − Expert_weapon_bonus − Armsmaster_bonus − other_reductions
GM_bonus = effective_Axe, если GM и хотя бы один разрешённый одноручный Axe; иначе 0
R_after_GM = R_before_GM − GM_bonus
R_final = max(30, R_after_GM)
Recovery_seconds = R_final / 60
```

`effective_Axe` — изученный ранг плюс существующие `skillBonus` (предметы и другие источники
движка); мастерство берётся из изученного навыка. GM10/20/30 добавляет −10/−20/−30 ticks.
При ведущем Axe сохраняется Expert −Axe, то есть суммарный вклад самого Axe равен −2×Axe.
Без других модификаторов это соответственно 80/60/40 ticks для GM10/20/30.
Для двух Axe дополнительный бонус остаётся одним, а не двумя.

Speed использует существующую нелинейную таблицу `parameterBonus`, а не числовой стат напрямую.
Armsmaster снижает Recovery на эффективный ранг, GM Armsmaster — на удвоенный ранг.
Haste даёт существующее снижение 25 ticks через `attackRecoveryReductionTicks`;
предметные и прочие прежние модификаторы сохраняются. Нижний melee-предел — 30 ticks (0,5 секунды).
Двуручный топор нового снижения не получает: его Expert Recovery остаётся прежним.
Новый GM-бонус не применяется к заклинаниям, стрелам и другим режимам атаки.

### Полный физический урон двуручного GM Axe

Урон оружия включает физический модификатор самого оружия и его диапазон кубиков.
К нему добавляются Might (`parameterBonus`), существующий Master Axe (+эффективный Axe),
Armsmaster (Master +ранг, GM +2×ранг), физические зачарования, постоянные/магические
бонусы ближнего боя. В смешанной паре бонус навыка к урону определяется **основной рукой**:
Master Axe прибавляет ранг, когда Axe справа; топор слева добавляет свой урон оружия,
но не второй бонус Master Axe. Общий Armsmaster применяется один раз. Might и Armsmaster учтены до нового множителя.

В существующем контроллере elemental входит в общий бросок урона и затем отделяется.
Поэтому точка удвоения находится **после** существующих модификаторов удара и множителя
предмета против вида монстра, но **до** отдельных проверок сопротивлений цели:

```text
physical_before = max(0, total_melee_damage − elemental_total)
GM_multiplier = 2 для двуручного Axe с GM и Physical; иначе 1
physical_after = physical_before × GM_multiplier
final_physical = existing_target_resistance(physical_after)
final_total = final_physical + отдельно обработанные elemental-компоненты
```

Удвоение целочисленное, без округления или проверки шанса; каждый физический компонент
проходит защиты ровно один раз. На предельных целых значениях новый множитель насыщается
до вместимости `int`, оставляя место elemental-компонентам. Обычное округление/случайные
проверки сопротивлений остаются прежними. AC по-прежнему влияет на попадание.

Одноручные Axe не получают ×2. Магические компоненты зачарований и отдельные on-hit эффекты,
заклинания и independent damage не удваиваются. Превращённый предметным эффектом
в Irresistible удар также не считается физическим. Recovery двуручного Axe не меняется.
Сравнение с тройным уроном Dagger не используется как шаблон: новая механика множит
именно всю отделённую физическую часть, а правила Dagger остаются прежними.
Показанный в листе персонажа исходный диапазон урона остаётся до применения к конкретной цели;
фактическое удвоение видно в боевом логе.

## Диагностика Axe

```text
config set axe_damage_trace true
config get axe_damage_trace
config set axe_damage_trace false
```

В `settings.ini`: `[debug] axe_damage_trace=false` по умолчанию. Канал независим от
`combat_trace` и `minotaur_damage_trace`, использует тот же файловый sink и путь
`[logging] combat_trace_file` (по умолчанию `logs/combat_trace.log`).
Для сохранения записей при переключении использовать `combat_trace_append=true`.
Во время игры открыть файл в текстовом редакторе; строки сбрасываются в файл сразу.
Новый executable нужен для новых команд настройки; старый Windows-пакет изменений не содержит.

Одна строка `axe_attack` объединяет урон и Recovery одного melee-действия с Axe в любой руке:
имя/класс/уровень, эффективный Axe и числовое мастерство (1 Normal, 2 Expert, 3 Master, 4 GM),
ID/имена/тип обоих оружий, `two_handed_axe`, цель, попадание и `raw_damage`.
Бонусы: `might_bonus`, `armsmaster_bonus`, `weapon_skill_bonus`, `enchantment_total_bonus`,
`physical_enchantment_bonus`, `flat_bonus`, `weapon_min/max`, `target_multiplier`.
Физический урон: `physical_before_gm`, `gm_multiplier`, `physical_after_gm`,
`final_physical_damage`; магическая часть отдельно в `elemental_before_resistance`.
Recovery: `recovery_before_gm`, положительная величина снижения `gm_recovery_bonus`,
`recovery_after_gm`, `final_recovery_ticks`, `final_recovery_seconds`.

`damage_resolved=false` означает, что действие не дошло до нанесения урона противнику
(например, промах или взмах без цели); нулевые промежуточные поля тогда не являются попаданием.
Recovery записывается и для таких действий. Диагностика только читает уже рассчитанные данные,
не делает RNG-бросков и не изменяет партию или боевую механику.

## Lethal Strike v0.4 — Implemented

Полный контракт: [дизайн](design/death-strike.md). Это единственное название нового навыка.
Class Minotaur / MinotaurLord получают Normal1 бесплатно сверх старых навыков. Другие классы,
включая персонажей другой профессии с расой Minotaur, не получают его. Создание, seed/roster,
найм и старые saves используют идемпотентную выдачу; существующие значения не сбрасываются.
Minotaur может обучиться до Master, Lord — до GM. Продвижение не выдаёт GM автоматически.

| Ранг | P0 в процентах |
| --- | --- |
| N | 0.60×S + B |
| E | 0.90×S + 0.56×V + B |
| M | 1.10×S + 0.64×V + B |
| GM | 1.30×S + 0.72×V + B |

B=`0.5*floor(max(0,currentLuck)/10)` п.п.; Luck90 даёт +4.5 п.п.
S/V — базовые Lethal Strike / Perception, без предметов. Ранг Perception значения не имеет;
нет Perception — V=0. Identify Monster не участвует. `delta=PL-ML`;
KL=`min(1.4,1+delta/60)` при delta≥0, иначе `30/(30+1.5*abs(delta))`.
Итог=`min(30,P0*KL*KG)`, дробная точность. NORMAL: KG=1 приHP>0;
GIANT: KG=1 только при `0<5*HP<3*maxHP`, иначе0. Ровно60% запрещено, ниже60% штрафа нет.
Одна проверка после обычного успешного melee любого оружия/Unarmed, включая dual wield;
не для стрельбы/магии/miss/objects/обычного убийства. Не добавлено иммунитетов по природе существа.

### Быстрый тест в отдельном сохранении

Открыть консоль, выбрать портрет нужного персонажа:

```text
player add Minotaur LethalTester
player level 50
skill set LethalStrike 10 2
skill set Perception 10 1
config set lethal_strike_trace true
config get lethal_strike_trace
```

`skill set <canonical-name> <level1–63> <mastery1–4>` — явная тестовая команда, без расхода очков.
Она проверяет class/race cap; GM для обычного Minotaur будет отклонён. Для теста Lord:

```text
player class MinotaurLord
skill set LethalStrike 10 4
skill set Perception 10 1
```

`player class` меняет класс выбранного персонажа для теста, не выполняет квест продвижения.
Обычное продвижение и учителей также проверить в игре; старые квестовые команды приведены выше.
Повышение через Skills должно списывать новый численный уровень очков:1→2 стоит2,2→3 стоит3.
Остальные навыки, число свободных очков при стартовой выдаче и LS после продвижения не теряются.

Для максимальной заметности экспериментальной механики: S20/V20/GM, итоговый cap30%.
При S10/V10/Expert RMB обязан показывать `Base Lethal Strike Chance: 14.60%`.
Повысить LS или Perception и снова открыть RMB: строка должна обновиться. При P0>30 показывается
сам P0; ограничение30% применяется к итоговому шансу. Без навыка положительного P0 нет.

Наносить обычные melee-атаки, включая Unarmed, двуручный Axe, два Axe и допустимую смешанную пару.
При срабатывании увидеть `<имя> delivers a Lethal Strike!`. Это стандартная status bar с High priority
на4секунды: следующий обычный урон не должен её мгновенно затирать. Сообщение появляется один раз,
только если мгновенная смерть реально обработана. Смерть от обычного урона отдельного сообщения не даёт.
Статус не требует show_hits=true; при его отключении LS остаётся видимым.

### GIANT и точная граница60%

Отключить bolster для простого численного опыта существующей опцией профиля, либо использовать
фактические maxHP/Level из trace. Создать одного Green Dragon (ID70, базовые maxHP700):

```text
actor spawn 70 1
```

Actor index и template ID — разные вещи. Первый наведённый melee с trace записывает `actor_index`.
Далее использовать полученный индекс N (в командах заменить N числом):

```text
actor health N 420
lethal chance N
actor health N 419
lethal chance N
```

`lethal chance` читает реального actor и печатает HP/maxHP, актуальный Level, категорию, P0 и шанс,
не делает RNG и не наносит урон. При420/700 шанс0, при419/700 полный min(30,P0×KL).
При bolster рассчитать границу по фактическому maxHP; точное60% целочисленно существует при maxHP кратном5.
В самом бою порог проверяется **после** обычного урона: старт при420 ещё может разрешить LS,
если обычный удар опустил HP ниже420 в этом же действии. Сверять `hp_after` в trace, а не стартовое HP.
Установка HP не меняет maxHP, не оживляет мёртвого actor и не выдаёт XP/добычу.

Проверить NORMAL-переопределения28–33,58–63,76–81,91–93,106–108 при полном HP;
Phoenix130–132 и Devil220–222 должны иметь GIANT. Остальной утверждённый реестр —
[CSV](research/lethal-strike-classification.csv). Unknown/custom template получает NORMAL и warning в trace.

### Диагностика

```text
config set lethal_strike_trace true
config set lethal_strike_trace false
config set minotaur_damage_trace true
config set axe_damage_trace true
```

По умолчанию все выключены. LS использует существующий sink `[logging] combat_trace_file`,
обычно `logs/combat_trace.log`; общий combat_trace включать не требуется.
Пример формата (числа/ID условны, не запись измеренного боя):

```text
[CombatTrace] lethal_strike action_id=17 member_name="LethalTester" member_class="MinotaurLord" member_level=50 skill=10 mastery=4 perception=10 actor_index=9 monster_id=70 monster_name="Green Dragon" monster_level=70 category=GIANT unknown_template=0 hp_before=430 hp_after=410 max_hp=700 luck=0 luck_bonus=0 P0=20.2 KL=0.5 KG=1 chance=10.1 roll=3.25 success=1 death_processed=1 skip=""
```

Miss/ordinary_kill/no_actor_target/no_skill/giant_hp_threshold/death_rejected объясняют пропуск;
`roll=none` означает отсутствие броска. `hp_after` — после обычного урона, до Lethal Strike.
`unknown_template` сопровождается warning. Выключение trace не меняет RNG/урон/Recovery/результат.
Успешный LS также записывается при общем combat_trace даже без отдельного канала.
